# AWR 0.8.1 — Reliable project updates and clearer progress

AWR 0.8.1 updates the personal CLI, MCP server and bundled Project Hub. It includes
the unattended takeover and checked-work features introduced in [0.8.0](0.8.0.md),
plus fixes for large projects, multilingual ledgers and completion evidence, and
an explicit sensitive-source admission policy.

## Highlights

- **Multilingual ledgers remain editable.** YAML block scalars containing multibyte
  text no longer shift subsequent source positions and produce a false
  `missing YAML mapping colon` failure. The scanner fix and source-position guards
  preserve the intended edit location (#640).
- **Larger projects can show their work graph.** The graph budget now supports up
  to 16,384 nodes through the same limit across callers, replacing the conflicting
  1,000-node ceiling (#639).
- **Completion evidence survives source refresh correctly.** A bare ledger
  reference can retain registered verification for the same project, work,
  branch and artifact. Conflicting versions remain unresolved, and changed report
  bytes invalidate completion instead of inheriting an older successful result
  (#642).
- **Sensitive-source handling is explicit.** Strict mode remains the default.
  Projects may opt into warn mode to read flagged sources while automatically
  redacting stored projections and returned content. Original files stay unchanged;
  warnings and receipts retain the location, category and operator (#643).
- **Project Hub shows the next useful step.** Project takeover cards show the
  inspect command, and work details expose read-only preparation information from
  AWR (#600, #518). Agents continue to execute the workflow through CLI/MCP.
- **Native packages include vendored dependency notices.** The license bundle
  includes third-party path dependencies, including the patched YAML parser, while
  retaining the selected platform's runtime and build dependency scope.

## Install and upgrade

```sh
npm install -g @originoneai/awr@0.8.1
# Or in a Python virtual environment:
python -m pip install originoneai-awr==0.8.1
awr --version
awr-mcp --version
```

The first ordinary AWR command or local MCP connection starts the bundled web
service. Open **http://127.0.0.1:7381**, or run `awr overview`. If that port is in
use, `awr overview status --json` reports the selected address.

The project database remains at schema 14. Stop existing writers and the Hub, back
up the matching project and per-user Hub state, install the new version, and run
`awr source reindex` once. See the [upgrade guide](DISTRIBUTIONS.md).

The earlier 0.8.0 publication reached PyPI only. This release supersedes it across
the supported distribution channels; its published PyPI files remain unchanged.

## Sensitive-source policy

From the project directory, inspect or explicitly change its policy:

```sh
awr policy secrets show
awr policy secrets warn --actor project-maintainer
awr policy secrets log
# Restore the default refusal behavior:
awr policy secrets strict --actor project-maintainer
```

Warn mode supports first initialization, including `init --write-draft`. It can
withhold a complete flagged text field or source-content response rather than
attempt an unsafe partial reconstruction. Partial line requests do not bypass
redaction. Policy and warning state are scoped to each project operation.
New writes, request/configuration inputs and recovery archives remain strict;
clean a flagged original before asking AWR to edit it. See
[sensitive-content boundaries](../reference/secret-boundaries.md).

## Scope

These packages contain `awr`, `awr-mcp` and the local Project Hub / Project Progress
Overview. Team PostgreSQL services and Observer have a separate deployment path.
The Team Beta is intended for collaborative delivery testing; a Beta label does
not certify that all real-agent business scenarios have passed.

Prebuilt payloads support macOS 15+ Apple Silicon and Intel, Linux x64/arm64 with
glibc 2.39+, and Windows x64. Launchers require Node 22.14+ or Python 3.9+.
The reported macOS 26 SQLite/restore failures remain tracked in
[#636](https://github.com/originoneai/awr/issues/636); macOS 15 CI does not establish
their resolution.
