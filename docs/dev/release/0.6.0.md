# AWR 0.6.0

AWR 0.6.0 updates the personal CLI/MCP packages from 0.5.1. The packages contain
the native `awr` and `awr-mcp` binaries only. Team code is compiled in but **off
by default** (see [Team runtime switch](#team-runtime-switch)); the Team service
and its PostgreSQL backend are not part of the packages.

## Upgrade notes

- **Store schema 7 → 14.** The first explicit database write, normally
  `awr source reindex`, applies migrations 008 to 014. They only add tables and
  indexes; existing data and IDs are unchanged. 0.5.x binaries cannot open the
  migrated database. Stop all writers and back up `.awr/state.db` (with
  `awr runtime backup` or SQLite's backup API), your sources and the old binaries
  first. See [Upgrading from 0.5.x](DISTRIBUTIONS.md#upgrading-from-05x-schema-7--14)
  for the migration table and rollback steps.
- **Concise prepare views (#352).** `work prepare` / `awr_work_prepare` in the
  `summary` and `action` views may now omit `context.work_context.omitted_chunks`
  when every entry has the known whole-chunk budget reason. The count is in
  `response_view.detail_counts`, and a `detail_note` explains it. A missing array
  does not mean zero omissions; request `full` to get every entry. `full` remains
  the default view. See the
  [concise-view contract](../integrations/host-workflow.md#optional-concise-results).
- **CLI completion evidence fields (#331).** The evidence object emitted by
  `awr work prepare-completion` now uses `work_item_key` and `branch_id`, so it
  can be passed directly to `awr evidence add --input`. MCP keeps `work` and
  `branch`.
- **Secret and search policy bump (#206).** Public boolean, null and empty
  literals are no longer treated as secrets. The secret policy (7) and search
  policy (9) versions changed: derived summaries are rebuilt from sources, and
  stale content reviews must be reassessed.
- **Project revision (#332).** Reindexing unchanged sources no longer advances
  the project revision.
- **Portable goal keys (#337).** New `awr init --accept` runs write portable goal
  keys. Existing projects are not rewritten.
- **`source relocate-recover` (#359).** A damaged receipt now returns
  `InvalidInput` (exit 1) instead of crashing.
- **Stricter intake source rule (#365).** Source writes to unregistered files under
  `.awr/intake/`, or to its `inventory.json` and `project.toml`, are now refused.
  Intake files created by `awr init` are registered and keep working.
- **Additive fields:** `warning` on completion preflight (#335), `last_event_at`
  on work graph and nav nodes (#269), MCP argument diagnostics (#315).

## Team runtime switch

`awr team`, `awr remote` and the MCP tools `awr_team_handoff` and
`awr_team_review` are off unless enabled (#363). When off, the commands exit with
a clear "team features are disabled" error and create no state, and the MCP tools
are not advertised. Enable them with `AWR_TEAM_ENABLED=1`, with `[team] enabled =
true` in `.awr/project.toml`, or with `team_enabled = true` in a shared MCP
registry. See [Team runtime switch](../reference/team-switch.md).

## New

- `awr work graph --cached` returns the last recorded graph without touching
  sources. (#266)
- `awr nav`: read-only mainline navigation across scope, dependencies and
  blockers. (#142, #267, #268)
- `awr session start --client/--conversation` binds a session to a host
  conversation; see the host contract for how this relates to `client bind`.
  (#334, #350)
- Opt-in assessment explanations for `work prepare` (`--explain` / `explain`),
  built on a typed assessment envelope with explicit unknown and conflict
  states. (#147, #148, #150, #151)
- `awr assessment` developer commands: offline replay, shadow compare and an
  advice kill-switch. (#152)

## Improved

- **Evidence stays current across unrelated ledger edits (#336, #349).** When
  another task changes a shared YAML ledger, evidence for an unchanged task stays
  `Current`, and its verified completion stays valid. Work queries, task context
  and completion revalidation use the work-scoped assessment. Standalone
  `awr evidence show` and Git/code revision checks stay strict. A completion
  receipt's selected proof is never silently replaced by another report. See
  [Concepts](../../series/concepts.md).
- Field-level diagnostics:
  - MCP argument rejections (#315);
  - completion-report failures across preflight, completion and revalidation (#321);
  - schema and binding validation failures (#324);
  - checkpoint fields (#330);
  - unquoted YAML evidence entries and dependency notes (#277, #278).
- Completion preflight reports non-canonical report line endings with the
  canonical digest, without refusing. (#335)
- Concurrent writes to single-file and sharded sources are protected. (#120)
- Dependency-graph validation reports cycle paths. (#105)
- Documentation: a rebuilt README and user series, Codex integration with grouped
  MCP, WorkBuddy and named-adapter notes, and the client-continuity vs MCP
  session-binding contract. (#159, #186, #193, #307, #312, #313, #350)

## Fixed

- `awr nav` reports cancelled or archived dependencies as waits and selects work
  by its source-declared goal. (#267, #268)
- The minimal context profile no longer reports a contradictory "rules source is
  missing" gap. (#273)
- Intake skips deep and generated directories instead of aborting `init`. (#322)
- Authored `.awr/intake` ledgers accept writeback and work creation. (#323, #338)
- A file under `.awr/intake/` counts as an authored source only if it is registered in
  `.awr/project.toml`, after symlinks are resolved; the runtime-written `inventory.json`
  and `project.toml` never do. Every source write, including sharded writes and
  organization field changes, now uses this one rule. (#365)
- Conflict proposals can be rejected, and interrupted work actions show recovery
  steps. (#325)
- `source relocate-recover` reports a damaged receipt instead of panicking. (#359)
- Relocated repository documentation resolves in builds. (#189)

## Platforms

macOS 15+ (Apple Silicon and Intel), Linux glibc 2.39+ x64/arm64 and Windows x64.
Launchers require Node 22.14+ or Python 3.9+. The Inspector is not bundled; run it
from the `v0.6.0` source checkout.
