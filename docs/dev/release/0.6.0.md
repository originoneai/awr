# AWR 0.6.0

AWR 0.6.0 updates the personal CLI/MCP release from **v0.5.1**. It adds opt-in
assessment explanations, field-level diagnostics, cached work graphs and read-only
mainline navigation, keeps evidence current across unrelated ledger edits, and
fixes intake, completion and recovery edge cases. Team code is compiled in but off
by default; the Team service and its PostgreSQL backend are not part of the packages.

## Changes

- **Team runtime switch:** `awr team`, `awr remote` and the MCP tools
  `awr_team_handoff`/`awr_team_review` are off unless enabled with
  `AWR_TEAM_ENABLED=1`, `[team] enabled = true` in `.awr/project.toml`, or
  `team_enabled = true` in a shared MCP registry. When off, the commands return a
  clear error and create no state, and the tools are not advertised. See the
  [Team runtime switch](../reference/team-switch.md). ([#363](https://github.com/originoneai/awr/pull/363))
- **Evidence currency:** when another task changes a shared YAML ledger, evidence
  for an unchanged task stays `Current` and its verified completion stays valid.
  Work queries, task context and completion revalidation use the work-scoped
  assessment; standalone `awr evidence show` and Git/code revision checks stay
  strict. A completion receipt's selected proof is never silently replaced.
  ([#336](https://github.com/originoneai/awr/pull/336), [#349](https://github.com/originoneai/awr/pull/349))
- **Assessment explanations:** opt-in `--explain` / `explain` for `work prepare`,
  built on a typed assessment envelope with explicit unknown and conflict states,
  plus `awr assessment` developer commands for offline replay, shadow compare and
  an advice kill-switch. ([#147](https://github.com/originoneai/awr/pull/147), [#148](https://github.com/originoneai/awr/pull/148), [#150](https://github.com/originoneai/awr/pull/150), [#151](https://github.com/originoneai/awr/pull/151), [#152](https://github.com/originoneai/awr/pull/152))
- **Navigation and graphs:** `awr nav` provides read-only mainline navigation
  across scope, dependencies and blockers, reports cancelled or archived
  dependencies as waits, and selects work by its source-declared goal.
  `awr work graph --cached` serves the last recorded graph without touching
  sources; graph and nav nodes carry `last_event_at`.
  ([#142](https://github.com/originoneai/awr/pull/142), [#266](https://github.com/originoneai/awr/pull/266), [#267](https://github.com/originoneai/awr/pull/267), [#268](https://github.com/originoneai/awr/pull/268), [#269](https://github.com/originoneai/awr/pull/269))
- **Usage, time and ETA accounting:** the local store records usage and
  execution-time receipts and ETA checkpoints from what the host reports. AWR
  does not measure usage itself; missing host data is shown as a gap.
  ([#139](https://github.com/originoneai/awr/pull/139), [#140](https://github.com/originoneai/awr/pull/140), [#141](https://github.com/originoneai/awr/pull/141), [#144](https://github.com/originoneai/awr/pull/144))
- **Session binding:** `awr session start --client/--conversation` binds a session
  to a host conversation; the host contract explains how this relates to
  `client bind`. ([#334](https://github.com/originoneai/awr/pull/334), [#350](https://github.com/originoneai/awr/pull/350))
- **Diagnostics:** field-level diagnostics for MCP arguments, completion reports,
  schema and binding validation, checkpoint fields, unquoted YAML evidence entries
  and dependency notes. Completion preflight reports non-canonical report line
  endings with the canonical digest, without refusing.
  ([#277](https://github.com/originoneai/awr/pull/277), [#278](https://github.com/originoneai/awr/pull/278), [#315](https://github.com/originoneai/awr/pull/315), [#321](https://github.com/originoneai/awr/pull/321), [#324](https://github.com/originoneai/awr/pull/324), [#330](https://github.com/originoneai/awr/pull/330), [#335](https://github.com/originoneai/awr/pull/335))
- **Intake and sources:** intake skips deep and generated directories instead of
  aborting `init`. Authored `.awr/intake` ledgers accept writeback and work
  creation. A file under `.awr/intake/` counts as an authored source only if it is
  registered in `.awr/project.toml`, after symlinks are resolved; the
  runtime-written `inventory.json` and `project.toml` never do, and every source
  write uses this one rule. Concurrent writes to single-file and sharded sources
  are protected. ([#120](https://github.com/originoneai/awr/pull/120), [#322](https://github.com/originoneai/awr/pull/322), [#323](https://github.com/originoneai/awr/pull/323), [#338](https://github.com/originoneai/awr/pull/338), [#365](https://github.com/originoneai/awr/pull/365))
- **Fixes:** dependency-graph validation reports cycle paths; the minimal context
  profile no longer reports a contradictory missing-rules gap; conflict proposals
  can be rejected and interrupted work actions show recovery steps;
  `source relocate-recover` reports a damaged receipt instead of panicking;
  reindexing unchanged sources no longer advances the project revision; public
  boolean, null and empty literals are no longer treated as secrets.
  ([#105](https://github.com/originoneai/awr/pull/105), [#206](https://github.com/originoneai/awr/pull/206), [#273](https://github.com/originoneai/awr/pull/273), [#325](https://github.com/originoneai/awr/pull/325), [#332](https://github.com/originoneai/awr/pull/332), [#359](https://github.com/originoneai/awr/pull/359))
- **Documentation:** a rebuilt README and user series, Codex integration with
  grouped MCP, WorkBuddy and named-adapter notes, and the client-continuity vs MCP
  session-binding contract. ([#159](https://github.com/originoneai/awr/pull/159), [#186](https://github.com/originoneai/awr/pull/186), [#193](https://github.com/originoneai/awr/pull/193), [#307](https://github.com/originoneai/awr/pull/307), [#312](https://github.com/originoneai/awr/pull/312), [#313](https://github.com/originoneai/awr/pull/313), [#350](https://github.com/originoneai/awr/pull/350))

## Install

```sh
npm install -g @originoneai/agent-work-runtime@0.6.0
# Or in a Python virtual environment:
python -m pip install agent-work-runtime==0.6.0
awr --version
awr-mcp --version
```

The same native CLI/MCP payloads are available for macOS 15+ arm64/x64,
Linux glibc 2.39+ arm64/x64 and Windows x64. Launchers require Node 22.14+ or
Python 3.9+. Keep npm optional dependencies enabled. The Inspector is not bundled
and must be run from the `v0.6.0` source checkout.

## Upgrade and rollback

Version 0.5.1 uses SQLite schema 7. Version 0.6.0 migrates **7 → 14** on the first
explicit database write, normally `awr source reindex`. Migrations 008 to 014 only
add tables and indexes; existing rows and project, work, source and evidence IDs
are unchanged. Stop concurrent writers and back up `.awr/state.db` (with
`awr runtime backup` or SQLite's backup API), configuration, sources and the old
binaries first.

Older binaries refuse schema 14. Downgrading a package alone is insufficient:
restore the verified matching pre-upgrade snapshot, preserve post-upgrade history
separately and never overwrite changed sources blindly. See
[Upgrading from 0.5.x](DISTRIBUTIONS.md#upgrading-from-05x-schema-7--14) for the
migration table and rollback steps.

Behavior changes that may need host updates:

- **Concise prepare views:** `summary`/`action` may omit
  `context.work_context.omitted_chunks`; read `response_view.detail_counts` or
  request `full`. A missing array does not mean zero omissions. `full` remains the
  default. ([#352](https://github.com/originoneai/awr/pull/352))
- **CLI completion evidence:** `awr work prepare-completion` emits `work_item_key`
  and `branch_id`, so the object can be passed directly to `awr evidence add --input`.
  MCP keeps `work` and `branch`. ([#331](https://github.com/originoneai/awr/pull/331))
- **Secret and search policies:** policy versions 7 and 9 rebuild derived summaries
  from sources; stale content reviews must be reassessed. ([#206](https://github.com/originoneai/awr/pull/206))
- **Intake sources:** writes to unregistered files under `.awr/intake/`, or to its
  `inventory.json` and `project.toml`, are refused. Intake files created by
  `awr init` are registered and keep working. ([#365](https://github.com/originoneai/awr/pull/365))
- **Portable goal keys** apply to new `awr init --accept` runs only. ([#337](https://github.com/originoneai/awr/pull/337))
- **Project revision** no longer advances on a no-op reindex. ([#332](https://github.com/originoneai/awr/pull/332))
- **`source relocate-recover`** returns `InvalidInput` (exit 1) for a damaged
  receipt. ([#359](https://github.com/originoneai/awr/pull/359))

## Release boundary

The packages contain the native `awr` and `awr-mcp` binaries built from the
workspace. Team code is compiled in but disabled by default; `awr-server` and the
Team PostgreSQL service are not packaged. Authenticated Team collaboration,
delivery review and versioned cross-workstream delivery adoption remain in
development. Schema migration and passing fixture tests do not establish complete
native-agent or Team business acceptance.

The release workflow binds scope, versions, native tests, installation checks and
all packages to one source SHA. npm/PyPI artifacts and GitHub assets must match
the assembled manifest and checksums. Validation results belong to that exact
release commit and its workflow run; historical PR CI is not release evidence.
