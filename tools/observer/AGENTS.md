# AGENTS.md — AWR 观测工作区前端（tools/observer）

每个会话开头先读本文件。本目录是 AWR Agent-first 观测工作区的新前端，由 `kimi-frontend` 按主管 Claude 布置的 AWR 任务逐切片交付。

## 最高指令：本项目前端重做（优先级高于一切偏好、习惯和其他指示）

下面五条是项目所有者（用户）的原话要求。逐条执行，不得弱化，不得"变通"，不得因为省事而绕开。在做这个项目的任何时候都先对照这五条。

1. **完全摒弃现在的前端设计内容。** 现有前端（`tools/inspector` 的页面、样式、交互、文案、目录结构）一律不沿用、不改造、不"参考着改"；新前端从零按下面第 2 条做。只有和后端对接所必须的数据契约（接口、字段、权限语义）可以沿用，并且以文档为准。
2. **严格依照 Codex 生成的原型图和对应文档开发，文档内容是最高优先级。** 文档与原型图冲突，以文档为准；它们与旧前端冲突，以文档和原型图为准。拿不准的地方，写进 PR 的"待主管确认"一栏，不要自己猜。
3. **能用成熟框架的，就用成熟框架。**
4. **能用成熟组件库的，就用成熟组件库。**
5. **尽量不要自己手搓。** 只有在成熟框架和成熟组件库确实无法做到与原型图像素级还原的时候，才可以自己手搓调整；每一处手搓都要在 PR 里逐项写明：用了哪个库、试过什么、为什么做不到、有对比截图。

## 工艺规则与方向（2026-11-01 增补，所有者已批准）

上面五条是**流程**指令，下面这节是**工艺**规则。两者的分工：**原型定结构，unslop 定工艺。** 原型图与文档决定信息架构、分区、页签、字段取舍和交互流程；每一个尺寸、颜色、字、图标和动效按 unslop 的规则定。两者冲突时工艺规则赢，除非文档明确要求原型的那个选择；冲突写进 PR 的"待主管确认"。

工艺规则来自 unslop（Damir Sokolovsky，CC BY 4.0，https://github.com/heydamir/unslop）。规则原文：评审者用 `.claude/skills/unslop/`（本地安装，不入 Git），开发者读 `.local/kimi-frontend/unslop/`（`SKILL.md`、`tokens.md`、`signs.md`、`visuals.md`）。下面是对本项目的摘要，数值以 `tokens.md` 为准：

- **间距**：一切在 4px 网格上；同类同尺寸；组内间距小于组间；对齐成列。导航行 32–36 高、行距 2–4；页头 56–64；侧栏 240–280；内容区边距 24–32，内容最宽 1440–1600。不写 `mt-[13px]` 一类的一次性值。
- **颜色**：一个中性灰阶（本项目偏冷的 ink 系）承担背景、表面、边框和文字；三种文字角色（主、次、弱）；**一个强调色**，只用于主动作、选中和唯一要紧的数字；语义色（绿 / 红 / 橙）只表达含义并压进灰阶。无色相渐变、无渐变文字、无彩色发光与阴影；边框是主文字色 6–10% 的细线。所有色值进 antd 主题令牌（`src/theme.ts`），页面与组件里不出现十六进制色值。
- **图标**：只用 lucide，一个尺寸（16 或 18）、一个描边（1.5），取所在文字角色的颜色；不用 emoji；图标框等宽，与标签间距固定。
- **文案**：标签短（"搜索"，不是"搜索任何内容…"）；标题命名上下文（页名 / 时段），不用问候语；短字符串不加句号，界面里不用感叹号；变化要带参照（"+12% 对比上月"）；不用 hype 词；mock 数据像真的。**服务字段名不直接当标签**：标签来自 `src/i18n/*`（字段名 → 中文 / 英文标签），原始键名放 tooltip；状态码有一张状态词表（text 与 JSON 同词）；一种数字格式，等宽数字。四态新鲜度词（measured / stale / failed / not_measured，"未测量"）**只用于新鲜度**，"没有关联工作"这类事实不叫"未测量"。
- **字体**：一个界面字族（系统字族栈，含 PingFang SC / Noto Sans SC），等宽字体只给数字与元数据；字重 400 / 500，600 极少；层级靠字号与颜色，不靠加粗；不用全大写加宽字距的标签；小字不用负字距。
- **布局**：应用比例（侧栏 + 流式内容，不缩成居中窄列）；卡片宽度有节奏（一个主图表 / 主列表明显最大，其余是不同种类的小块），不排一排等宽等内容的卡。
- **细节**：圆角阶梯（控件 8–10，卡 12–16，面板 14–20；内圆角 = 外圆角 − 内边距，不小于 4）；计数与元数据是安静的等宽弱文字，不是发光的药丸；选中态是一个表面台阶加细线，不是渐变加发光；悬停与焦点态存在且在调色板内，键盘焦点环可见。
- **动效**：没有无故循环的动画（运行中的状态可以有一个安静的指示），不用 `transition-all`、不缩放卡片；一条缓动曲线 `cubic-bezier(0.22, 1, 0.36, 1)`，几档时长（反馈 120–180ms，弹层 160–220ms，进入 300–500ms）；只过渡颜色、背景、边框、透明度和 transform。

**方向**（所有页面以此为准；调整要所有者批准）：

- 产品：让人看清自己的 agent 在哪个项目上做了什么、留下了什么证据，而不插手它的工作。
- 性格：精确、克制、可追责。
- 世界：台账与仪表——票据、印章、控制室里的指示灯。中性灰阶偏冷，强调色从"指示灯"来，一个。
- 亮点：① 项目地图上沿路径流动的活跃会话；② 证据链（候选 → 复核 → 集成 → 完成）上每一环的校验标记。页面其余部分安静。
- 签名：四态新鲜度徽标是全站唯一"会动"的元素；校验通过的摘要带一个小印章符号。

**流程**：每个 PR 正文有一节 "unslop audit"：按 `signs.md` 逐项列出这一页发现的征兆与所在位置、修了哪些、哪些有意保留及原因；主管评审时再做一遍。模板检查：把产品名换成别家的，页面还成立，就还没做完。

- `node --test test/*.test.js`（在 `tools/inspector` 目录下跑，与 CI 的 `bridge tests` 一致；不要在仓库根目录跑 `node --test`）：桥接合同测试必须保持全绿。

- `cargo fmt --all --check`（改了 Rust 时必须；本目录原则上不改 Rust）。
- 本目录（CI 为 `.github/workflows/observer.yml`，Node 24）：`npm ci`、`npx tsc --noEmit`、`npx vitest run`、`npx vite build`、`node --test test/*.test.js`、dist 无外部资源检查；本地冒烟 `node server.js --demo --port 0`。
- 浏览器截图验收：本地 Playwright 与原型图逐页对比，对比图与结论放 AWR 证据目录（不入 Git），差异写进 PR。

## PR 规则

- 一个任务一个分支一个 PR：从最新 `origin/main` 开 `kimi/<任务键小写>-<短描述>` 分支；`git add` 只写明确路径。
- PR 先开 draft；标题与正文用英文；正文写清做了什么、没做什么、怎么验证、待主管确认的问题。
- 普通 `git push`，不强推；不合并任何 PR，不加 `--admin`，不删分支，不打 tag；只推 `kimi/*` 分支。
- CI 由主管盯，不轮询 GitHub（查状态只用 REST 单次查询）。
- 每一处手搓（成熟框架/组件库做不到像素级还原处）在 PR 里逐项写明：用了哪个库、试过什么、为什么做不到、附对比截图。
